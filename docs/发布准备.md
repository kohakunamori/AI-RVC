# 发布准备与验收

## 1.6.0 候选版（2026-10-23）

源码 `VERSION`、Compose 默认标签与 Docker OCI 构建版本统一为 `1.6.0`。本轮在现有 `master` 分支更新，将 TelkNet 的同源音频改动移植为本项目的独立实现；没有增加 TelkNet 服务依赖。功能、修复和来源见 [CHANGELOG](../CHANGELOG.md) 及 [同源更新记录](TelkNet同源更新.md)。稳定版公开下载仍是 `1.5.1`；本节不复用旧版成品的验收结论。

本机实测环境为 Windows、RTX 4070 Ti SUPER 16 GB、PyTorch 2.11.0+cu126、audio-separator 0.47.0。五首花丸歌曲各耗时 321.68–340.19 秒；完整参数与逐首结果见同源更新记录。此次没有重新测量峰值显存、系统内存峰值或磁盘峰值，也没有用相同环境重新运行 1.5.1，因此这些峰值及相对上版速度变化均为未验证；不能据此宣称性能提升。

提交后对同一源码运行 `Platform Contracts`、四种 `Build Executables` 审核构建和两种 `Docker Images` 检查。草稿说明应记录实际提交及对应 Actions 链接；只有成功的运行可列为通过。角色权重、索引、原曲、试听输出与本机私有证据目录不提交。

## 1.5.1 历史发布与验收

本版 `VERSION`、Compose 默认镜像标签与 OCI 构建版本统一为 `1.5.1`。实际分发的文件、分卷、SHA-256 及本次 Actions 结果以 [v1.5.1 Release](https://github.com/mason369/AI-RVC/releases/tag/v1.5.1) 为准。本文保留发行要求与候选阶段证据，不能将未实测的平台列为已经通过。1.5.0 草稿缺少 UVR5 固定源码，早期 1.5.1 候选的 Linux CUDA 包漏收 NVRTC 内置库，均被成品验收拦截，未公开发布；修正后的全套成品沿用 1.5.1 版本重新构建。准备与打包前后校验覆盖全部 495 个固定源码文件；NVIDIA 动态库按安装环境完整收集，GPU 包另外执行无需显卡的 NVRTC 实际编译检查。

## 发布前必须核对

1. 在最终源码上执行 `python -m unittest discover -s tests`，重新构建多轨资源，完整依赖 `pip check` 通过。
2. 用实际权重完成默认六模型翻唱，核验七类音频、参数、有限采样值与 Float WAV，并由用户亲自试听、检查页面；新缺陷未解决时停止发布。
3. 分别验收实际要分发的 Windows/Linux CPU/CUDA 包和 Docker 镜像；源码或设备探针通过不能替代运行包通过。缺少硬件的后端明确标为未验收或实验性。
4. 对照上一版包的运行依赖、上游源码、模型、配置、前端资源和入口清单解释增删。PolarFormer 不得残留在新发行资产中；角色权重不因本地存在就自动进入发行包。
5. 每个便携目录生成 `PACKAGE-MANIFEST.json`，压缩包与分卷生成对应 `SHA256SUMS`，下载后复核。README 引用的公开图片和文档一并打入便携包；GPU 包须通过 NVRTC 实际编译，Linux NVIDIA 动态库与构建环境逐项对照。
6. 核对 `VERSION`、Git 标签、源码提交、OCI 标签和文档指向同一版本；本机模型、录音、凭据、AGENTS.md 及私有记录不能提交或进入容器上下文。

## 工作流约定

`Build Executables` 手动运行默认只生成 Actions 审核产物。上传发行资产必须显式指定与 `VERSION` 一致的标签，并选择 `publish`；推送版本标签也要求目标 Release 已存在且仍为草稿。工作流检出该标签源码，拒绝把任意分支构建覆盖到“最新 Release”。四种包全部完成并复核之后，再发布草稿。

`Docker Images` 手动运行只构建和检查，不推送仓库；正式发布 Release 后才构建并推送 GHCR 的明确版本 CPU/CUDA 标签及 SBOM/来源证明。托管 runner 没有 NVIDIA GPU，只能验证 CUDA 镜像构建和依赖，真实 GPU 翻唱需使用本地验收证据。当前只声明 `linux/amd64`，没有把 ARM64 模拟构建当作真机验收。

发布完成后核对实际可下载的全部附件与 GHCR 镜像，再回复相应 issue，说明修复版本、升级方法和实际验证范围。源码、候选记录与最终分发产物分别记录。
